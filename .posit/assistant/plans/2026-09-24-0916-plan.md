# Fall back to earlier submission rounds when building `country_prefill`

## Problem
`country_prefill[[iso]][[measure]]` powers the pre-filled "Country Question
Format" answers shown in each indicator's panel. It's built in `global.R`
from `data/previous responses.RDS`, which is now one long tibble with
columns `question, response, measure, ref_area, year` (one row per question
per submission round, instead of the old per-country list-of-tibbles shape).

The current conversion (global.R:462-476) collapses each
`(ref_area, measure)` group down to **only its single most recent round**
via `group_by(ref_area, measure) %>% slice_max(.yr, ...)` *before* any
question-level matching happens. If a country answered a question in an
earlier round (e.g. Mexico, 4_3, 2023) but that same question is blank/NA in
their latest round, the earlier answer is discarded entirely and the field
renders empty - even though a usable answer exists in the data.

There's also a stray debug snippet at global.R:459-460
(`readRDS(...) %>% filter(measure == "4_3", ref_area == "MEX") %>%
drop_na()`) left over from investigating this, printed with no output
target - safe to remove as part of this fix.

## Fix
Change the fallback granularity from "most recent round per measure" to
"most recent **non-missing answer per question**", so each question field
independently falls back through earlier years:

1. Remove the early `group_by(ref_area, measure) %>% slice_max(...)`
   collapse. Keep `.prev_resp_raw` as the full long tibble, split by
   `ref_area` (one tibble per country, all rounds/years included).
2. Inside `country_prefill`'s per-measure builder function:
   - For each country/measure subset `prev`, sort rows by year descending
     (parsed numerically via `suppressWarnings(as.numeric(year))`; rows
     with unparseable/missing year sort last so they're never preferred
     over a dated round).
   - For each question label `i`, find all rows matching that exact
     question text **with a non-NA, non-empty response**, and take the
     first one in the (already year-descending) order - i.e. the most
     recent round that actually has an answer for that specific question.
   - This naturally implements "check latest year; if NA, check 2023; if
     still NA, check 2022; ..." per question, rather than per
     country/measure as a whole.
3. Remove the stray debug lines at global.R:459-460.
4. Sanity check after the change (read-only inspection, e.g. via a
   throwaway console check once out of Plan mode): Mexico's 4_3
   `country_prefill` should now be populated from 2023 answers where 2025
   (or whichever is latest) is blank, and a spot check on another
   country/measure with a fully-answered latest round should show
   unchanged output (still prefers the latest round when it has answers).

## Out of scope
- No changes to how `country_prefill` is consumed in `app.R`
  (`build_response_html`, etc.) - only how it's built in `global.R`.
- No changes to `nonused_dat`, `oecd_comments`, `latest_request`, or other
  loaders.
- Not touching the earlier purple-border / OECD-comment-icon work from
  prior turns.
