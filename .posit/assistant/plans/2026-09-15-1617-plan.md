# Plan: Comma decimals, breakdown-consistency warning, attachment notes

All changes are in `app.R` (no changes to `global.R` needed).

## 1. Accept commas as decimal delimiters (convert to periods)

The numeric input fields currently strip commas as the user types, and all parsing uses `parseFloat()` / `as.numeric()` which don't accept commas.

**Primary fix — convert commas to periods at input time** in the two `oninput` handlers:

- `app.R:3215` (well-being year inputs) and `app.R:2547` (time-use Table 1 numeric cells):
  change
  `oninput="this.value=this.value.replace(/[^0-9.\-]/g,'')"`
  to
  `oninput="this.value=this.value.replace(/,/g,'.').replace(/[^0-9.\-]/g,'')"`

  Commas become periods instantly, so every downstream `parseFloat()` (range validation line 56, submit line 151, collect line 223, time-use lines 546/600/623) works unchanged. This also covers the "Paste from spreadsheet" modal, since `applyPastedData()` (line 444) dispatches a bubbling `input` event that fires these handlers.

**Server-side fix — Excel bulk upload** (`app.R:2432`):
change `as.numeric(val)` to `as.numeric(gsub(",", ".", val, fixed = TRUE))` so uploaded workbooks with comma decimals parse correctly.

**Defensive normalization** at the two client parse points that receive raw values (`parseFloat(inp.value)` at lines 151 and 223): wrap as `parseFloat(String(inp.value).replace(',', '.'))` in case a comma slips through (e.g., browser autofill).

## 2. Non-blocking warning: breakdown values vs. country average

New client-side check, run only on **Submit** (not Save and continue), after the existing blocking range validation in `submitMeasure()` (`app.R:140`).

**Logic** (new JS function `checkBreakdownConsistency(container, measure, safe_id)` added near `validateMeasureRanges`, ~line 90):

- Look up the measure's range from `window.__validRanges[measure]`; if none, skip.
- Threshold: **40% of the range span** (e.g., gap > 4 on a 0–10 scale, > 40 pp on percentages, > 9.6 h on 0–24).
- Read the `country_avg` row's value per year; for every other row **except `vert` and `dep`** (different concepts/units), compare same-year values.
- If any gap exceeds the threshold:
  - Highlight offending fields with an **amber** border (`2px solid #F89C1C`) — visually secondary to the red blocking style.
  - Set the status line (`status_<safe_id>`) in amber: "N value(s) differ substantially from the country average for the same year (highlighted in orange). Please double-check them."
  - Show a `confirm()` pop-up: "Some breakdown values look very different from the country average for the same year — are you sure they are correct? Press OK to submit anyway, or Cancel to review."
  - **OK → submission proceeds** (amber highlights remain as a reminder); Cancel → abort submit, user can edit.
- If no offenders, clear any previous amber borders and proceed silently.

Call site: in `submitMeasure()` right after `validateMeasureRanges` (line 140):
```js
if (!validateMeasureRanges(container, measure, safe_id)) return;
if (!checkBreakdownConsistency(container, measure, safe_id)) return;
```

Notes:
- Indicators with only a country-average row (or no country average, e.g. 8_2) are naturally unaffected — no comparison pairs exist.
- Clearing/reverting inputs already resets borders to `1px solid #ccc`, so amber styling is cleaned up by existing code paths.
